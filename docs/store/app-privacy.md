# App Store 개인정보 라벨 (App Privacy) 답안

근거: 백엔드 `backend/migrations/0001`~`0008` 의 실제 저장 컬럼, `backend/crates/api/src/routes/`, 앱 `pubspec.yaml`(분석·광고·충돌 보고 SDK 없음, 위치 권한 없음).
`data-safety.md`(Google Play)와 같은 사실을 적어요. 둘 중 하나를 고치면 다른 쪽도 고치세요.
App Store Connect → 앱 → [앱 개인 정보 보호] 에 아래대로 입력해요.

## 공통
| 질문 | 답 |
|---|---|
| 개인정보를 수집하나요? | 예 |
| 추적(Tracking)에 사용하나요? | **아니요** (광고 식별자 IDFA 미사용, ATT 요청 없음, 제3자 광고·분석 SDK 없음) |
| 개인정보처리방침 URL | `https://도메인/privacy.html` |
| 계정 삭제 | 앱 내 [더보기] → [계정] → [회원 탈퇴], 웹: `https://도메인/delete-account.html` |

|---|---|---|---|---|---|
| 연락처 정보 · 이름 | 이름 | `users.name` | 예 | 아니요 | 앱 기능, 계정 관리 |
| 연락처 정보 · 이메일 | 이메일 (소셜 로그인 시만) | `users.email` (nullable) | 예 | 아니요 | 계정 관리 |

| 연락처 정보 · 실제 주소 | 도로명 주소, 상세 주소, 평수 | `addresses` | 예 | 아니요 | 앱 기능 (배정된 파트너에게 전달) |
| 구입 항목 | 예약 내역, 결제 금액, 쿠폰 사용 | `bookings`, `payments`, `checkouts`, `coupons` | 예 | 아니요 | 앱 기능 |
| 결제 정보 | 결제수단 토큰(빌링키), 표시명(예: 카드 끝 4자리) | `payment_methods` | 예 | 아니요 | 앱 기능 (결제) |

| 식별자 · 기기 ID | 푸시 알림 토큰 | `push_tokens` | 예 | 아니요 | 앱 기능 (알림) |
| 사용자 콘텐츠 · 사진 | 상담·청소 사진 | `uploads`, `bookings.photos` | 예 | 아니요 | 앱 기능 |
| 사용자 콘텐츠 · 고객 지원 / 기타 | 앱 내 채팅 메시지, 후기 | `chat_messages`, `reviews` | 예 | 아니요 | 고객 지원, 앱 기능 |

Apple이 따로 묻지 않는 항목: **건강·피트니스, 민감 정보, 연락처(주소록), 위치(GPS 없음, 직접 입력한 주소만), 검색 기록, 브라우징, 진단(크래시 보고 SDK 없음), 사용 데이터(분석 없음)** → "수집하지 않음".

## 판단이 필요한 항목 (확인 후 입력)
1. **결제 정보 (고객)**: 서버는 카드 번호를 저장하지 않지만 결제대행사(PortOne)가 준 **빌링키 토큰**을 `payment_methods.billing_key` 에 저장해요. 이 토큰으로 카드 결제가 가능하므로 "결제 정보 — 수집함, 연결됨, 앱 기능"으로 답하는 것이 안전해요. (data-safety.md 는 "결제 카드 정보: 수집하지 않음"이라고 적었는데, 이 부분을 같이 고쳤어요.)
2. **본인확인 CI**: `users.ci_hash` 에는 CI 의 SHA-256 해시만 저장하고 원문은 저장하지 않아요. 식별 목적의 해시이므로 "식별자 · 사용자 ID"에 포함해 답하는 것을 권장해요.
3. **위치**: 기기 위치 권한은 요청하지 않아요 (`Info.plist` 에 위치 사용 문구 없음). 사용자가 입력하거나 고른 주소만 저장해요. 실제 주소 검색 API 를 붙이면 이 항목을 다시 확인하세요.

## 바뀌면 같이 고칠 곳
- 새 테이블/컬럼에 개인정보가 들어가면 이 표와 `data-safety.md` 를 같이 고쳐요.
- 분석·광고·크래시 SDK를 붙이면 "추적" 또는 "진단/사용 데이터" 행을 추가하고, 그 SDK 의 데이터 공유 항목을 Google 양식에도 적어요.
